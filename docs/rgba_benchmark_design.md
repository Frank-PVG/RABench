配套的无参考图 T2RGBA 方案见 T2RGBA 设计（外部项目资料：`AlphaLift/docs/t2rgba_benchmark_design.md`），两者共用分类和质量标尺，各自保留任务适用的评分依据。

本版根据讨论收敛为只设计 I2RGBA。一级分类固定为“半透明物体”和“不透明物体”，在各大类内部细分；边缘形态、孔洞、目标大小、背景难度等使用附加标签。核心集优先具有可追溯、可验收的 RGBA 参考答案。

## 1. 主任务定义

输入一张 RGB 图像和指定目标的自然语言指令，输出该目标在原画布中的 RGBA 图层。要求保留目标的位置、尺度、形状、颜色和可见细节，移除背景与非目标元素。

一期核心集建议选择完整可见的目标。画面可以有多个干扰物，目标本身不被其他前景物体遮挡。半透明目标后面的背景仍然存在，这正是需要分离的内容。

这一选择使核心评测集中在指代与图层提取。完整物体补全、被遮挡的背景恢复、改变物体外观等任务以后单列，避免隐藏区域有多种合理答案而影响主榜。

参考 GT 表示制作时已经固定的目标图层，并不意味着单张半透明输入在数学上只有一种可能分解。数值误差与多背景视觉可用性应共同检查。

## 2. 两级分类：半透明 3 类，不透明 8 类

分类对齐当前 GPT 生产 taxonomy v8（外部项目资料：`AlphaLift/scripts/data_pipeline/generate/rgba_prompt_taxonomy.yaml`），其原始类别为 person、animal、object、plant、product、graphic、effect、advertising_asset。

生产类别是语义/用途分类；半透明与不透明是图层属性，二者不是同一维度。Benchmark 保留每个样本的原始生产类别，再增加透明度一级分类和下面的评测子类。半透明侧归并为 3 类，不透明侧直接沿用 8 个生产类别。

### 一级：半透明物体

包括透明物体。判断依据是目标本体存在需要在 RGBA 中表现背景透过的部位，不以“有软 alpha 像素”作为唯一标准。

| 二级类别 | 内容范围与例子 | 对齐的 GPT 生产类别 |
| --- | --- | --- |
| 半透明实体 | 玻璃瓶、透明塑料、薄纱、薄膜、凝胶、水母；包含应恢复半透明部件的混合材质主体 | person、animal、plant、object、product 中相应样本 |
| 半透明特效 | 烟雾、火焰、光晕、渐隐粒子、透光液体飞溅等 | effect 中相应样本 |
| 半透明图形与广告元素 | 半透明水彩、透明色块、玻璃质感文字/按钮、半透明标签、渐隐装饰 | graphic、advertising_asset 中相应样本 |

玻璃、薄纱、液体、生物透明部件等只作为实体类内的覆盖标签，不再全部列为独立二级配额。烟雾、火焰、光效等同理。

物理材质相似的内容可以因为原始用途而出现在不同类别：作为商品的玻璃瓶属于半透明实体，玻璃质感标题属于半透明图形与广告元素；原生产类别消除两者的分配歧义。

### 一级：不透明物体

直接沿用 GPT 的 8 个语义类别，避免重新合并人物/动物、物体/商品、图形/广告素材。

| 二级类别 | GPT 类别 | 内容范围与例子 |
| --- | --- | --- |
| 人物 | person | 人像、全身人物、角色；发丝、衣物细节作为标签 |
| 动物 | animal | 哺乳动物、鸟类、昆虫、爬行动物等；毛发、羽毛、触须作为标签 |
| 植物 | plant | 花、叶、树枝、草、根系等 |
| 普通物体 | object | 道具、器物、工艺品、织物、镂空物件等 |
| 商品 | product | 数码设备、包装、鞋包、美妆、家电等商品资产 |
| 图形 | graphic | 图标、几何图案、纹样、装饰形状、实色笔触等 |
| 特效 | effect | 不透明纸屑、花瓣、实心颗粒、金属或不透明颜料飞溅等 |
| 广告素材 | advertising_asset | 广告文字、促销标签、按钮、标注框、信息组件与广告装饰 |

保留不透明特效有实际依据：当前 effect 主体池中包含 paper confetti、flower petals、liquid-metal droplets、milk splash 等候选。它们是否进入不透明分支仍由实际 GT 判定，不依据名称强制指定。

object 与 product 等类别边界沿用原生产分类，已有来源标签的样本不重新随意改类。新采集素材按同一语义/用途约定标注。

### 映射示例

| 原始生产类别与样本 | 实际图层属性 | Benchmark 归属 |
| --- | --- | --- |
| product：透明护肤滴管瓶 | 本体透底，瓶盖可以不透明 | 半透明 → 半透明实体 |
| animal：水母 | 伞部透底 | 半透明 → 半透明实体 |
| graphic：半透明水彩色块 | 内部有透明度层次 | 半透明 → 半透明图形与广告元素 |
| advertising_asset：实色促销文字 | 本体不透底 | 不透明 → 广告素材 |
| effect：纸屑飞散 | 纸片本体不透底 | 不透明 → 特效 |

### 分类规则与横向标签

- 毛发、抗锯齿和运动模糊引起的局部非二值 alpha，不自动把不透明物体变成半透明物体。
- 不透明丝线之间可分辨的孔洞属于镂空结构；整体呈透底效果的薄纱按实际图层进入半透明实体。
- 反光、浅色、高光，以及仅有透光照明感的材质，不自动要求 alpha 小于 1。
- 混合材质目标只要含本次任务必须恢复的有效半透明部件，就归半透明大类，并保留混合材质标签；其中的不透明部件必须保持不透明。
- 透明度大类由人工结合原始图层确认，不按整图平均 alpha 或生产类别自动决定。
- effect 不等于半透明，person/animal/product 也不等于不透明。

细线、毛发、孔洞、软边、混合材质、目标面积、偏心位置、允许裁切、风格、背景难度、多对象干扰、指令形式等都保留为横向标签，不继续增加主类别。

每个样本既能按上述 Benchmark 分类统计，也能按 GPT 原始类别统计。这样可以把评测短板对应回训练数据的语义分布，而不牺牲半透明分支的紧凑性。

## 3. 建议规模与分配

先保留 240 个独立资产作为一期预算基线，透明度两大类各 120 个。一级类别数量均衡，不要求所有二级类别数量相同；两大类内部再做子类宏平均。

| 阶段 | 不透明物体 | 半透明物体 | 独立资产合计 | 每资产 3 个背景后的输入—GT 对 |
| --- | ---: | ---: | ---: | ---: |
| Pilot 开发集 | 40 | 40 | 80 | 240 |
| v1 全部核心集 | 120 | 120 | 240 | 720 |
| 其中封存测试部分 | 80 | 80 | 160 | 480 |

按当前分类的起步配额：

- 不透明 8 类：每类 15 个，其中开发 5 个、测试 10 个。
- 半透明 3 类：每类 40 个。开发数量依次 14、13、13，测试数量依次 26、27、27。
- Pilot 全部留在开发集，不能重新进入隐藏测试。
- 若 Pilot 显示某个二级类别的测试区间过宽，再增加该类别的新独立资产。上述规模是起步预算，不保证足以区分很小的性能差异。

背景变体是重复观测，不是新的独立目标。720 对图像的独立资产数仍为 240。

真实场景中暂时没有可靠 GT 的案例只作为附加定性检验，不计入本版核心数量和像素指标主榜。

## 4. GT 的获得方式

### 4.1 从已确认的 RGBA 图层构造输入

一期的主要路线是先获得并验收目标 RGBA，再用统一合成流程生成 RGB 输入。这样目标的前景颜色、alpha、位置和尺度都有明确来源。

目标来源包括：

1. 原生图层资产：自绘/委托制作的插画、文字、图标、分层设计，保留源工程。
2. 控制渲染资产：用训练未用过的模型、材质、VDB sequence 等制作毛发、薄纱、烟雾等，保留渲染参数和原始通道。
3. 经专业修订的摄影图层：同时处理边缘 alpha 和前景颜色污染，达到多背景验收标准。这里的 GT 是已定义、可合成使用的图层资产，不声称它就是唯一的物理分解。

把自然 RGB 与预测 mask 拼在一起，不足以自动获得合格 GT。半透明像素可能保留旧背景颜色，反复乘 alpha 后仍会出现色边或底纹。

同样，生图/抠图模型直接输出的 RGBA 可以作为候选，但经过检查、修订之前不能自动升级为 Gold。尤其不能用被测模型自己的输出给自己制作标准答案。

### 4.2 对半透明 GT 加强验收

不透明物体主要检查目标主体、边界和孔洞。半透明物体必须额外检查内部前景颜色和透明度能否配合，在不同背景上呈现合理结果。

对于普通 SDR 图层，允许采用设计或渲染制作的玻璃、水花等二维素材。它们有明确的资产 GT，可以检验模型能否从已知合成图中恢复该资产。

对具有强折射的真实玻璃，固定 RGBA 无法完整表示随新背景变化的折射、反射和光照。几何覆盖率也不是物理透明度真值。[TOM-Net](https://guanyingc.github.io/TOM-Net/)采用遮罩、衰减和折射流，体现了这种表示差异。

因此保留玻璃类别，但清楚记录它是“二维图层资产提取”还是“真实折射场景”。前者满足核心任务定义后可以进入 Gold，后者没有可靠的普通 RGBA 答案时进入附加案例，不混入精确 GT 主榜。

### 4.3 可控实拍作为补充路线

对静止物体固定相机、曝光和光照，采集多个不同背景，再拟合前景和 alpha；使用未参与拟合的背景检查误差。

背景变化也可能改变物体的照明和反射，毛发运动也会破坏像素对齐。只有通过独立背景验证的结果才作为可信参考。此路线需要先做小规模可行性检查，不作为一期必须完成的全部 GT 来源。

### 4.4 保存合成约定

固定 RGB 颜色空间、straight/premultiplied alpha、合成规则、位深和几何变换。不能仅凭“16-bit PNG”就认为 GT 正确。

建议保存高质量原始资产，正式推理统一到 1024×1024，采用等比缩放和明确的画布变换，避免拉伸。物体的大小和位置应有变化，不把所有目标都居中放大。

源工程采用不同合成方式时，必须按来源核验。需要进入统一主协议时从已确认图层重新合成，不直接假设已有成稿与新规则严格一致。

## 5. 输入和指令设计

每个独立资产制作三种背景输入，目标 RGBA 在三个版本中保持一致：

| 输入背景 | 作用 |
| --- | --- |
| 普通背景 | 检查基本提取能力 |
| 低对比背景 | 检查目标与背景颜色接近时是否丢失或误透明 |
| 复杂背景 | 检查纹理污染、多对象干扰和目标选择 |

复杂背景可以含同类物体，指令要能唯一指定目标。目标前方不放遮挡物；目标后方的背景可以透过半透明目标，这是核心任务的一部分。

指令使用自然表达，主要覆盖外观指代、位置指代，以及位置加外观的组合。每个样本只有一条预先固定的主指令，改写版本仅作为附加鲁棒性分析，避免重复计数。

例子：

- 提取左侧带金属盖的透明瓶，保留原来的位置和大小。
- 提取画面右侧的黑猫，保留细毛发和胡须。
- 将浅蓝色纱巾单独提取为透明图层，保留其褶皱和细穗。
- 提取上方写着“春日特惠”的黄色文字及绿色描边。

模型只看到 RGB 和任务指令；不提供 GT、背景底图、参考遮罩、框或 trimap。需要额外输入的方法单列设置。

## 6. 逐张验收

最终核心资产建议由两人独立验收，有分歧再裁决。只有一人验收的前期样本先作为开发候选。

所有样本均查看黑底、白底、彩色底、棋盘底、独立 alpha、原尺寸与局部放大图。

| 公共检查 | 要求 |
| --- | --- |
| 文件和对齐 | RGB/alpha 对齐，画布和方向正确，没有导出错误 |
| 主体完整性 | 无非预期裁切、缺肢、缺叶、断字或遗失部件 |
| 背景污染 | 无旧背景底纹、非预期白边黑边、矩形底板、棋盘烘焙 |
| 指令正确性 | 指向唯一目标，完整/可见层语义明确，描述与 GT 一致 |
| 来源与处理 | 来源、许可状态、修订历史、分组与内容校验信息齐全 |
| 合成一致性 | 独立重新读取与合成，确认没有双乘 alpha 或颜色转换错误 |

不透明大类额外检查：主体内部没有不合理的透明孔洞或整体变淡；真实孔洞能够透底；毛发和细线不过度裁除。

半透明大类额外检查：透光部位没有被二值化；透明度层次和前景颜色相互匹配；稀薄区域没有非预期截断；混合材质中的不透明部件没有一起变透明。

自动统计只用于提示。软像素比例低不一定差，连通分量多也不一定差；验收必须结合物体类别和图层用途。

## 7. 评价方式

### 7.1 共同主指标

建议共同报告以下四项：

1. 指令成功率：是否提取了正确对象，是否保留规定的位置和大小。
2. Alpha 误差：对比 GT 的透明度与范围，分别统计全图和 GT 预定义目标区域。
3. 多背景合成误差：把预测和 GT 分别合成到相同的黑、白、灰和彩色背景，比较实际可见结果。
4. 人工可用率：该结果是否可以直接用于正常尺寸的合成，是否需要修复严重边缘、颜色或主体缺失问题。

多背景评价可以暴露原背景上不明显的底色污染，公开 RGBA 评价中也有类似做法，见 [AlphaVAE](https://arxiv.org/html/2507.09308v1)。

输入时的三个场景背景与评分时的标准背景是两个不同环节：前者测试提取对背景的敏感性，后者测试输出图层本身。

仅合成回原始输入不能充分说明 RGBA 正确，因为不同的前景颜色和 alpha 可能解释同一张 RGB 输入。

### 7.2 两大类分别关注什么

| 大类 | 重点分项 |
| --- | --- |
| 不透明物体 | 不透明主体保留、边界细节、孔洞正确性、毛发细线完整性、颜色纹理保真 |
| 半透明物体 | 透光部位 alpha、前景颜色贡献、多背景表现、局部浓淡层次、混合材质部件保真 |

Alpha MAE、边缘 Gradient/Connectivity、预乘颜色误差和合成 LPIPS 可作为相应诊断。透明区的任意隐藏 RGB 不应直接决定得分。

目标区域、边界带和透光区域由 GT 或预先标注确定，不能由预测自行缩小。小目标同时报告全图和目标区域，避免空背景稀释误差。

半透明物体的评价不能只强调外轮廓；不透明物体的评价也不能只用是否有软 alpha 来判定质量。

### 7.3 汇总与公平性

分别报告不透明物体、半透明物体的结果，以及各二级类别和横向标签的结果。两个大类等权汇总时，仍保留各分项，避免用一个总分隐藏问题。

同一资产的三个输入背景先在资产内汇总，再统计类别均值和置信区间。所有模型使用相同测试输入和预先固定的输出选择规则，不挑选最好 seed，不手工修边。

失败、缺图、空输出和错误目标必须记录；可用性失败计入分母。连续误差注明有效输出数，不能只展示成功样本的均值。

人工盲评隐藏模型名、随机候选顺序并允许平局。项目 AlphaReward 可以用于开发诊断；被测模型若用过它训练或选 checkpoint，正式结论需要独立评审。

## 8. 避免训练污染

按原始资产、设计、拍摄场景或模拟 sequence 分组后划分开发和测试，再制作背景和文字变体。

同一对象换背景、换视角、换材质、换帧、换裁剪或换图层，不应进入另一集合。已有 SFT、DPO、GRPO、RM 使用过的素材，不能简单换一种导出方式就成为独立测试数据。

检查来源 ID、内容 hash、感知近重复以及必要的人工复核。测试背景来源也尽量与开发背景分开。对无法确认的基础模型预训练重叠，报告可核验范围。

Pilot 用于修改规则和观察模型表现，因此全部归开发集。正式测试样本在规则冻结后验收、封存。

## 9. 一期执行顺序

1. 固定半透明 3 类、不透明 8 类，以及它们与 GPT 原始类别的映射。
2. 按两大类各 40 个制作开发资产，共 80 个；逐张检查 GT、指令和三背景输入。
3. 用代表性方法做小规模比较，并用已知白边、alpha 硬化、细节丢失、错目标等退化校准评审。
4. 检查验收一致性、每类制作成本和评分区分度；修改规则只使用开发样本。
5. 规则冻结后，按第 3 节配额补充未参与调参的新资产，共 160 个封存测试资产。

这样一期最终获得 240 个独立 RGBA 资产、720 对 RGB 输入与 RGBA GT，其中正式隐藏测试为 160 个资产、480 对输入。没有可靠 GT 的真实案例、遮挡补全和额外光学表示，留作明确标注的附加研究。

## 10. 项目现有能力怎样承接

GPT 生产管线（外部项目资料：`AlphaLift/scripts/data_pipeline/generate/README.md`）的八类主体池、风格与配色可以作为内容覆盖依据。对齐类别不等于复用已经训练过的图片；核心测试仍使用来源隔离的新资产。生产类别和 Benchmark 分类同时保留，便于对照训练分布与评测短板。

PrismLayers 管线（外部项目资料：`AlphaLift/scripts/data_pipeline/filter/README.md`）已有图层恢复、合成检查、文字与空间指代，可承接设计图层候选和指令制作。需要检查来源是否已进入训练，并采用本版核心任务的完整可见目标要求。

辅助渲染管线（工作目录的 `tools/data_pipeline/render/`）已有薄纱、VDB 和玻璃相关能力，可承接候选制作；半透明素材仍需按本版的 GT 定义逐张验收，RCTrans coverage 不能直接作为普通 RGBA 物理透明度 GT。

本阶段只确定上述设计，不实现采集、标注或评测代码。
